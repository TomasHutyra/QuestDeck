# QuestDeck — Implementation Documentation

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Expo SDK 54 + React Native 0.81 |
| Language | TypeScript (strict) |
| Navigation | `@react-navigation/native-stack` |
| State | Zustand 5 + `persist` middleware |
| Persistence | AsyncStorage via `jsonStorage` adapter |
| Sound | `expo-audio` (createAudioPlayer) |
| Haptics | `expo-haptics` |
| Safe area | `react-native-safe-area-context` |
| Build | Gradle 8 / Kotlin 2.1 |
| Min Android | API 24 (Android 7.0 Nougat) |
| Package name | `com.BookdragonDev.QuestDeck` |

## Adding a New Quest Pack

1. **Create the JSON file**

   ```
   src/data/quests/adventure.json
   ```

   Same schema as `free.json`. Set `packId` to your new pack id (e.g. `"adventure"`).

2. **Register in `src/data/quests/index.ts`**

   ```ts
   import adventureQuests from './adventure.json';
   export const allQuests: Quest[] = [
     ...freeQuests,
     ...adventureQuests,
   ] as Quest[];
   ```

3. **Register in `src/data/packs.ts`**

   ```ts
   {
     id: 'adventure',
     name: 'Adventure Pack',
     description: '25 outdoor and travel quests.',
     isPremium: true,
     emoji: '🏔️',
     questCount: 25,
   }
   ```

4. **Unlock logic** — `packStore.unlockedPackIds` controls access. Add unlock logic in `PacksScreen` when payment is implemented. For testing, add `'adventure'` to the default `unlockedPackIds` array in `packStore.ts`.

5. **Validate**

   ```bash
   npm run validate:quests
   ```

## Adding a New Mood

1. **Add the type** in `src/types/index.ts`:
   ```ts
   type Mood = ... | 'new-mood';
   ```

2. **Register in `src/data/moods.ts`**:
   ```ts
   { id: 'new-mood', label: 'New Mood', emoji: '🎯' }
   ```

3. **Tag quests** — add `"new-mood"` to the `moods` array of relevant quests in `free.json`.

4. The mood button appears automatically in the `HomeScreen` grid (FlatList over `MOODS`).

## Adding a New Screen

1. **Create** `src/screens/NewScreen.tsx` with a `SafeAreaView` from `react-native-safe-area-context`.

2. **Register in `src/navigation/RootStack.tsx`**:
   ```ts
   // In RootStackParamList:
   NewScreen: { someParam: string };

   // In the navigator:
   <Stack.Screen name="NewScreen" component={NewScreen} />
   ```

3. **Navigate to it**:
   ```ts
   navigation.navigate('NewScreen', { someParam: 'value' });
   ```

## Build Process

### Debug build (development)

```bash
npx expo run:android
```

Installs a debug APK signed with the debug keystore. Metro bundler serves the JS bundle over USB.

### Release build (for Play Store)

```bash
cd android
gradlew bundleRelease
```

Output: `android/app/build/outputs/bundle/release/app-release.aab`

Signed with `android/app/questdeck.keystore` using credentials from `android/gradle.properties`.

### Regenerating the native Android project

If `android/` gets corrupted or after changing `app.json` (icons, package name, plugins):

```bash
npx expo prebuild --platform android
```

This regenerates `android/` from `app.json`. The existing `android/app/build.gradle` signing config and keystore are preserved if you run without `--clean`.

## Signing

The release keystore is at `android/app/questdeck.keystore`.  
Credentials are stored in `android/gradle.properties` (gitignored).

**Back up the keystore.** If it is lost, you cannot publish updates to the same Play Store listing.

## AsyncStorage Keys

| Key | Store | Contents |
|-----|-------|----------|
| `questdeck-quests` | questStore | `completedQuests[]`, `lastRevealedQuestIds[]` |
| `questdeck-progress` | progressStore | XP, level, streaks, lastCompletedDate |
| `questdeck-packs` | packStore | `unlockedPackIds[]` |
| `questdeck-settings` | settingsStore | sound, haptics, onboardingSeen |

To reset all app data: **Settings → Reset all data**, or uninstall the app.

## Key Design Decisions

**No backend.** All state is local. This eliminates auth, GDPR complexity, server costs, and network failure modes. The trade-off is no cross-device sync (acceptable for v1).

**Static quest data in JSON.** New quests ship with app updates. This avoids a CMS and keeps the app fully offline. The trade-off is that quest fixes require a Play Store update.

**Zustand over Redux.** Minimal boilerplate, built-in `persist` middleware, direct store access outside React (`useXStore.getState()`) needed by `completeQuest.ts`.

**`completeQuest` as a plain function, not a hook.** Called from `CompletionScreen` once on press. Reads from stores directly via `.getState()` to avoid stale closure issues.

**Pre-sized logo asset.** `logo_header.png` (186×132) is a pre-rendered 3× version of the brand logo. React Native's new architecture (Fabric) does not reliably scale very large bitmaps in small containers, so the image is pre-sized to avoid runtime scaling.
